\chapter{Ingegnerizzazione del sistema, REST API e containerizzazione}

\section{Backend REST API (FastAPI)}
\begin{sloppypar}
Il backend del sistema è realizzato in Python mediante il framework \textit{FastAPI}. Il servizio interagisce con MongoDB \textit{Gold} ed espone tre endpoint principali: \texttt{GET /cases} per ottenere l'elenco dei casi clinici registrati; \texttt{GET /cases/\{case\_id\}/series} per recuperare la serie temporale di un caso con supporto all'aggregazione temporale lato database (\textit{downsampling}); \texttt{POST /cases/\{case\_id\}/detect} per eseguire i modelli di \textit{anomaly detection} e salvare i risultati su MongoDB.
\end{sloppypar}

\section{Dashboard web interattiva}
Per la visualizzazione intuitiva dei dati è stata realizzata una \textit{dashboard} web in HTML5/CSS3/JavaScript, con l'ausilio della libreria \textit{Chart.js} per i grafici interattivi. L'interfaccia consente all'operatore sanitario o all'analista di selezionare interattivamente un caso dal registro, esplorare i grafici temporali sovrapposti delle cinque metriche vitali, ed avviare l'\textit{anomaly detection} visualizzando i marcatori delle anomalie sovrapposti ai tracciati biometrici.

\section{Containerizzazione ed orchestrazione con Docker}
L'intero ecosistema è completamente containerizzato ed orchestrato tramite Docker e Docker Compose. Il container \texttt{vitaldb\_mongo} ospita un'istanza di MongoDB 8.0 avviata automaticamente come \textit{Replica Set} (\texttt{--replSet rs0}) con verifica di salute nativa (\textit{healthcheck}), mentre il container \texttt{vitaldb\_api} contiene l'istanza dell'API \textit{FastAPI} basata su Python 3.12-slim, isolata nella rete interna di Docker. L'avvio dell'intero ambiente di sviluppo e produzione viene effettuato con il singolo comando:
$$\texttt{docker compose up --build -d}$$

\section{Conclusioni e sviluppi futuri}
Il progetto ha dimostrato con successo l'efficacia dell'integrazione tra moderne pipeline di \textit{data engineering} ed algoritmi avanzati di \textit{anomaly detection} per il dominio sanitario. L'architettura \textit{Medallion} su MongoDB Time Series ha permesso di ottenere miglioramenti misurabili sia in termini di qualità del dato sia di prestazioni di accesso, mentre l'approccio ibrido alla rilevazione di anomalie, combinando regole cliniche e \textit{machine learning}, garantisce una copertura più ampia degli eventi di interesse.

Tra i possibili sviluppi futuri figurano l'integrazione di motori di \textit{streaming} in tempo reale (ad esempio Apache Kafka) e l'estensione del tracciamento ad ulteriori indicatori fisiologici.
